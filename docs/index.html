git-commit-sentinel for Bitbucket

A Bitbucket Data Center plugin that checks pushes to feature branches against Conventional Commits.

Bitbucket Data Center 9.4 · Java 17 · off / warn / error per rule

The server-side twin of git-commit-sentinel: same rules, same names, same defaults. The client hook gives feedback at commit time; this plugin enforces on push.

Install

Download git-commit-sentinel-bitbucket-<version>.jar from the latest release (its SHA-256 is in SHA256SUMS.txt), then upload it from Administration → Manage apps → Upload app.

Bitbucket 9.4 disables uploading apps by default: start it with -Dupm.plugin.upload.enabled=true (e.g. in JVM_SUPPORT_RECOMMENDED_ARGS) to allow it.

On every push

$ git push origin feature/login
remote: git-commit-sentinel: 1a2b3c4 on feature/login: "wip: stuff"
remote: git-commit-sentinel:   error: [type] type "wip" is not in the allowed list: feat, fix, ...
remote: git-commit-sentinel: 5d6e7f8 on feature/login: "fix: the bug."
remote: git-commit-sentinel:   warning: [description-period] description must not end with a period
 ! [remote rejected] feature/login -> feature/login (pre-receive hook declined)

Only commits new to the repository are checked, on feature branches (feature/.+ by default). Merge commits, tags and other branches never are. Control characters in commit messages and branch names are shown as visible \u{...}, never sent raw to the terminal.

Rules

RuleDefaultChecks
formaterrorheader matches <type>(<scope>)!: <description>
typeerrortype is one of the allowed types
description-emptyerrordescription is not empty
description-periodwarndescription doesn't end with .
header-lengthwarnheader ≤ the max length (100 characters)
body-blank-linewarnblank line separates header and body

Configure

Enable Git Commit Sentinel in a project's Settings → Hooks: every repository of the project is checked. A repository can override the project's settings, or disable the hook. Blank fields use the defaults above. Or, from a provisioning pipeline:

Enable on a project, with settings 
curl -X PUT "$BB/rest/api/1.0/projects/PAY/settings/hooks/com.github.bluenoah.git-commit-sentinel-bitbucket:commit-sentinel-hook/enabled" \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"types":"feat,fix,chore","rule-description-period":"error","bypassUsers":"ci-bot"}'
KeyMeaning
branchPatternJava regex matched against the whole branch name
typesallowed types, comma-separated
headerMaxLengthin characters
rule-<name>default / off / warn / error
bypassUsersusernames never checked, comma- or newline-separated

Exempt CI pushes

A push made with a project or repository HTTP access token comes from a bot user such as access-token-user/1/3, one per project or repository. Put that name in bypassUsers:

Find the bot user of a project's access tokens 
curl -s -u admin "$BB/rest/access-tokens/latest/projects/PAY" | jq -r '.values[].user.name'
